# 项目优化记录

## 1. LangGraph v0.1.0 版本优化

- TTFT：2608.20 ms
- Total：5536.60 ms
- FCP：0.80 s
- LCP：0.80 s

说明：本次记录为优化前基线。TTFT 指从浏览器发起聊天请求到收到第一个非空 SSE 内容的耗时。

### 1. LLM 首 Token 响应时间优化：第一阶段

- 日期：2026-07-18
- 基线 TTFT：2608.20 ms

### 已实施

- 为聊天请求增加分段耗时日志：`request_received`、`conversation_ready`、`user_message_saved`、`history_loaded`、`redis_ready`、`memory_loaded`、`agent_created`、`model_request_started`、`first_model_token`、`first_sse_yielded`。
- Redis 客户端改为应用级懒加载共享实例，移除每次请求前的同步 `ping()`。
- 用户消息保存与历史读取并行执行，历史查询排除当前消息。
- 发送给 Agent 的历史限制为最近 20 条消息且最多 12000 字符。
- SSE 响应增加 `X-Accel-Buffering: no`。
- 修正文档为 UTF-8 编码并统一指标格式。

- 日期：2026-07-18
- 测试次数：10 次成功请求
- 测试方式：使用 `--runs 10 --warmup`，预热请求未计入统计

- 统计结果
- 浏览器端 TTFT 平均值：1295.97 ms
- 模型到后端 SSE 的平均额外耗时：20.32 ms
- 后端 SSE 到浏览器的平均额外耗时：13.42 ms

### 2. TTFT 自动测试脚本

- 日期：2026-07-18
- 脚本：`backend/scripts/measure_ttft.py`

使用方式：

```powershell
python backend/scripts/measure_ttft.py --url http://localhost:8000 --runs 20 --warmup
```

脚本调用 `/api/chat/send`，解析最后一个 `done: true` SSE 事件，并统计 `backend_model_ttft_ms`、`backend_sse_ttft_ms` 和浏览器端 TTFT。失败请求不计入平均值。

### 3. LLM 首 Token 响应时间优化：第二阶段，LLM 客户端连接复用

- 日期：2026-07-18
- 改动：缓存 `ChatOpenAI` 实例，复用其底层 HTTP 客户端。
- 未改动：模型名称、系统提示词、工具集合和 API 协议。
- 代码验证：后端编译、LLM 实例缓存复用检查、统计脚本百分位计算和前端生产构建均通过。

- 日期：2026-07-18
- 测试次数：20 次成功请求
- 测试方式：使用 `--runs 20 --warmup`，预热请求未计入统计

- 统计结果

| 指标 | 平均值 | 中位数 | P95 | 最小值 | 最大值 | 标准差 |
|---|---:|---:|---:|---:|---:|---:|
| `backend_model_ttft_ms` | 1739.94 ms | 1724.80 ms | 2400.52 ms | 1109.71 ms | 2410.40 ms | 419.99 ms |
| `backend_sse_ttft_ms` | 1816.92 ms | 1859.69 ms | 2431.30 ms | 1126.14 ms | 2437.99 ms | 432.98 ms |

- 浏览器端 TTFT 平均值：1823.93 ms
- 模型到后端 SSE 的平均额外耗时：76.98 ms
- 后端 SSE 到浏览器的平均额外耗时：7.01 ms

- 结论

- 本轮平均 `backend_model_ttft_ms` 比此前 10 次测试的 1262.23 ms 高 37.8%，不能证明连接复用带来收益。
- 当前主要瓶颈仍在模型服务或模型请求处理阶段，不在前端 SSE。
- 模型 TTFT 标准差为 419.99 ms，最大值比最小值高 1300.69 ms，存在明显服务端波动。
- 当前应优先检查模型服务排队、网络区域、Prompt 输入长度、工具定义和模型供应商能力，不继续调整前端 SSE。
